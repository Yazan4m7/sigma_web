3D Printing Specifics: The 3D printing process has 3 distinct stages:

 1 Waiting Stage:
    • Cases are queued for printing
    • Admin assigns cases to specific printers
    • Multiple cases can be grouped into a "build"
 2 Active Stage:
    • Printer is running the build
    • Progress is tracked
    • Can view details of all cases in the build
 3 Completion Stage:
    • Build is finished
    • Cases are moved to next stage (Sintering)
    • Printer becomes available for new builds

 1 Printer Management:
    • View all printers and their status

    • Name and track builds
    • Monitor build progress
 3 Case Details:
    • View all jobs in a case
    • See materials, colors, styles
    • Track progress through stages

Design Stage: Cases start here when first entered into the system

Cases undergo initial design and preparation

Milling Stage: Cases move here for milling operations

Machines/devices are selected for milling
Cases are "nested" on machines
After milling completes, cases move to next stage

3D Printing Stage: Cases that need 3D printed components

Operator selects printer and creates a "build"
Multiple cases can be grouped into a single build
Builds are set, started, and then completed

Sintering Stage: For cases requiring sintering

Cases are assigned to furnaces/sintering machines
Operators monitor and complete the sintering process

Pressing Stage: For cases requiring pressing operations

Similar to sintering with specialized equipment

Finishing Stage: Manual refinement and detailing

Cases are manually processed by technicians
Special conditions like "Not Ready" or "Abutment Missing" affect processing

QC (Quality Control) Stage: Quality verification

Cases are inspected for quality
Can be sent back to previous stages if issues are found

Delivery Stage: Final stage before reaching customers

Cases are assigned to delivery drivers
Delivery vouchers are generated
Options for direct delivery or "Delivered in Box"

Each stage has two states:


Waiting: Cases ready to be processed

Active: Cases currently being processed

## Build/Test Commands
- Install dependencies: `composer install`
- Run development server: `php artisan serve`
- Build frontend assets: `npm run dev`
- Run all tests: `./vendor/bin/phpunit`
- Run single test: `./vendor/bin/phpunit --filter test_name tests/Path/To/TestFile.php`
- Run artisan commands: `php artisan [command]`

## Code Style Guidelines
- Follow PSR-2 standards with Laravel conventions
- Classes: PascalCase (e.g., `UserController`)
- Methods/variables: camelCase (e.g., `getUserById`)
- Use type hints and return types where possible
- Models use Eloquent ORM with proper relationships
- Controllers should be thin, with business logic in dedicated services
- Use Laravel's error handling via app/Exceptions/Handler.php
- Frontend uses Bootstrap with custom styling
- Comment complex logic but avoid redundant comments

## Project Structure
- Laravel standard directory structure
- Models in both app/ and app/Models/ directories
- Views use Blade templating engine
- Operations workflow is handled in admin-dashboardv2.blade.php with 8 stages, each with different workflows
- The 3D printing, milling, and sintering stages (IDs: 2, 3, 4) require a buildName parameter
- The pressing stage (ID: 5) does not require buildName
- OperationsUpgrade.php extends CaseController for handling workflow dialogs and images

## Recent Changes Made
- Fixed missing 'type' parameter in form submissions in waiting-dialog.blade.php
- Updated STAGE_CONFIG to properly mark stages that require buildName (milling, 3dprinting, sintering)
- Fixed JavaScript issues with buildName field selection and validation
- Improved error handling and logging for buildName validation
